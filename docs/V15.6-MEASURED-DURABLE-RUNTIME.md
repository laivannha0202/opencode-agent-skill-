# UES 15.6 — Measured Runtime & Durable Execution

UES 15.6 turns several V15.4/V15.5 observability and concurrency contracts into enforceable runtime behavior without weakening verification or safety.

## Release goals

- make tool concurrency enforceable rather than descriptive;
- make warm child reuse dependent on a complete immutable runtime epoch;
- make controller progress recoverable after a process boundary without replaying uncertain side effects;
- reduce weak-model tool-choice noise while preserving the selected thinking level;
- make reversible output compaction adapt only from measured recall demand;
- preserve bounded rollback evidence for small file writes without touching unrelated dirty work;
- produce operator-visible run artifacts and an inspect/compare path;
- keep real-model quality claims separate from deterministic contract verification.

## 1. Durable Run Journal V2

`lib/run-journal.mjs` stores bounded JSONL events under `.ues-work/journals/`. A small atomic admission sidecar preserves the run identity even when old JSONL rows are compacted. Admission is idempotent for the same run payload. A conflicting retry with the same run ID fails closed. When controller admission is idempotent (the same run is resumed), the controller invokes journal recovery before starting new specialist work; any prior `tool.started` event without a terminal tool event is recorded as `tool.interrupted` with `replayed: false`. The runtime does not infer that a side effect did or did not complete and does not execute it again automatically.

Important invariants:

- journal/admission metadata stores task hashes rather than raw task text;
- event sequence is serialized by a bounded cross-process lock, so parent and child writers cannot reuse the same sequence number;
- interrupted side effects are evidence, not instructions to replay;
- journal write failure is treated as observability degradation and must not manufacture verification evidence.

## 2. Runtime Epoch

`lib/runtime-epoch.mjs` creates an immutable epoch ID from:

- policy snapshot ID;
- workspace fingerprint;
- context snapshot identity;
- tool surface hash;
- selected micro-skill surface hash;
- model runtime profile hash;
- model identity and thinking level.

The warm Pi RPC worker key includes the epoch ID. A policy-compatible but context/tool/model-incompatible worker is therefore not silently reused.

## 3. Model Runtime Profiles

`lib/model-runtime-profile.mjs` exposes compact, balanced and expanded orchestration surfaces. These are not quality rankings. They control bounded infrastructure choices such as advertised tool count and safe read parallelism. The profile explicitly preserves the host-selected thinking level.

For a compact profile in deep/recovery execution, `editPipeline` may become `architect-editor`; this reuses the existing architect/executor separation rather than introducing another agent.

## 4. Enforced Tool Scheduler

`lib/tool-scheduler.mjs` consumes the V15.5 Tool Concurrency Contract at the child boundary together with Pi's native per-tool `executionMode`:

- explicit bounded reads/searches remain parallel-capable up to the model/runtime read cap;
- built-in writes and process tools are re-registered with native `executionMode: "sequential"`, so a mixed sibling batch is serialized by Pi before execution instead of waiting inside preflight;
- dynamic/unknown conflicting surfaces fail closed with non-blocking admission and are retried only after current results settle;
- the scheduler never waits on a conflicting lease from `tool_call` preflight, avoiding a read/write sibling deadlock;
- queue/admission latency remains bounded and is attached to tool telemetry where applicable.

Task-level resource leasing remains separate. The child scheduler does not replace worktree/task isolation; it closes the per-tool execution gap.

## 5. Adaptive Compaction V2 policy

V15.6 keeps the existing command-aware reducers in `lib/performance-fabric.mjs` and the exact raw Evidence Store payload. `lib/adaptive-compaction.mjs` only adjusts the model-visible budget after enough compaction-recall observations exist.

Default policy:

- recall demand >= 35%: preserve 1.5x visible budget;
- recall demand >= 20%: preserve 1.25x;
- recall demand <= 5%: compact to 0.75x;
- insufficient samples: keep the existing budget.

All budgets remain bounded. Recall history can tune presentation, never alter raw verification evidence.

## 6. Runtime Hook Bus

`lib/runtime-hooks.mjs` provides deterministic observe/modify/deny lifecycle hooks. Critical hook failures deny rather than silently permit. V15.6 uses this as an internal contract surface; it does not load arbitrary external scripts by default.

## 7. Bounded Write Checkpoints

`lib/write-checkpoints.mjs` captures exact pre-write bytes only for bounded regular files. After the write, the checkpoint is finalized with post-write hashes. Rollback first checks every participating current file against the finalized hash. Any divergence refuses the whole rollback. Checkpoint capture and restore also fail closed on symlink traversal so a path inside the workspace cannot redirect recovery outside the workspace.

This is intentionally not a hidden Git reset, stash or shadow repository. It never authorizes mutation of inherited dirty work and does not weaken the existing dirty-work guard.

## 8. Run Artifact Bundle and Inspector

Controller runs may create:

```text
.ues-work/runs/<runId>/
  RUN.json
  VERIFICATION.json
  TELEMETRY.json
  SUMMARY.md
```

`npm run inspect:run -- last` reads the journal/artifact surface and reports event counts, terminal state, scheduler queue time, duplicate tool signatures, dangling tool calls and available artifacts. `--compare <runId>` compares bounded operational deltas.

## 9. Evaluation contract

`npm run eval:v15.6` is a deterministic contract gate. It proves scheduler, epoch, journal, hook, compaction-policy, checkpoint and artifact behavior. It does **not** prove that a real model is faster, cheaper or more accurate.

Real-model evidence remains the paired Pi-native path:

```cmd
npm run eval:pi -- --model <provider/model> --thinking <level> --suite live --mode both --trials <N>
```

For a release claim, compare identical tasks/model/thinking and report pass rate, verifier pass, false-pass, wall time, tokens, tool calls, retries/recovery and scheduler/LSP timing only when the provider actually reports them.

## 10. Safety and quality invariants

V15.6 must not weaken:

- independent verifier and integration/visual gates;
- Evidence Store and reversible raw evidence;
- dirty-work and `.env` mutation guards;
- workspace containment and destructive-command policy;
- fail-closed incomplete diagnostics;
- Repo Map V3 / Semantic Index V3;
- Holdout D evidence history;
- the user's selected thinking level.

Performance optimizations are promoted only when verification remains at least as strict. Missing telemetry stays unavailable rather than being converted to a fabricated zero.

## 11. Release gate

Before publishing:

```cmd
npm run release:verify
```

`prepublishOnly` also runs this gate. Real-model A/B is reported separately as MEASURED or NOT MEASURED because provider credentials and cost are environment-dependent.
