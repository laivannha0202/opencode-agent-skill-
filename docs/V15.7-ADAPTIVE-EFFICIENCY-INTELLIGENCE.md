# UES 15.7 — Adaptive Efficiency Intelligence

UES 15.7 builds on the durable V15.6 runtime. It does not lower model thinking, verifier rigor or safety. The release adds measurement-driven efficiency controls around command execution, provider-cache stability, model-visible output, solution complexity and paired real-model trials.

## Release goals

- prevent verification commands from hiding behind model-selected multi-hour timeouts;
- distinguish stable provider-cache prefix from newly produced live-zone evidence;
- route model-visible reduction by command, content type, task phase and measured recall demand;
- keep efficiency accounting separate from correctness claims;
- expose repeated tool work, queue pressure, interrupted tools, compaction recall and provider recovery as measurable runtime waste;
- prefer reuse/native/stdlib/already-installed primitives before adding new implementation, but only after the real flow is understood;
- make paired baseline-vs-UES real-model trials one command.

## 1. Command Intelligence V3

`lib/command-intelligence.mjs` classifies verification commands, likely long-running services and shell pipelines that reduce progress visibility.

The child runtime now clamps verification timeout to the UES policy even when the model supplied a larger timeout. A command such as:

```sh
npm test 2>&1 | grep ... | tail -45
```

is recorded as `verification-output-hidden-by-pipeline`. The command is not silently rewritten. Exact execution remains authoritative; UES only prevents the command from bypassing the bounded verification timeout and records the visibility hazard.

Long-running foreground service commands remain routed to the managed `ues_service` path.

## 2. Provider Cache Stability V1

`lib/provider-cache-stability.mjs` learns only from provider-reported token telemetry already stored by UES.

Modes are descriptive runtime policies, not model-quality labels:

- `cache`: measured cache-read share is high; keep the stable prefix untouched and reduce only the live zone;
- `balanced`: mixed measured cache benefit;
- `token`: measured cache benefit is low; the live zone may use a tighter visible budget;
- `neutral`: insufficient evidence, preserve the existing conservative behavior.

The policy is measurement-gated. UES follows Pi's normalized disjoint usage accounting: prompt-side volume is `input + cacheRead + cacheWrite`, and `input` is the uncached-input bucket rather than a total that already includes cache reads. Missing provider token telemetry produces `NOT_MEASURED`, never a fabricated zero.

The selected cache policy participates in Runtime Epoch identity, so a warm Pi worker is not silently reused after the effective cache policy changes.

## 3. Content Router V2

`lib/content-router-v2.mjs` classifies new tool output into bounded content classes such as:

- diff;
- JSON;
- tests;
- diagnostics;
- logs;
- code;
- search output;
- generic text.

The route combines content type with task phase. Verification/review diffs and source-like evidence preserve a larger visible budget than repetitive JSON/log payloads.

This does not replace the V15.1 command-aware reducers. It selects the live-zone presentation budget before `compactReversibleOutput`; the exact raw output still goes to Evidence Store first.

## 4. Adaptive visible budget

The model-visible tool-output budget is now the bounded composition of:

1. the configured base limit;
2. V15.6 measured compaction-recall policy;
3. V15.7 content-route multiplier;
4. V15.7 provider cache mode.

Only newly produced tool output is reduced by this path. UES does not rewrite already-admitted conversation history merely to improve a compression percentage.

## 5. Efficiency Ledger V2

`lib/efficiency-ledger.mjs` persists bounded operational observations under ignored `.ues-learning/` state.

It separates provenance:

- `MEASURED`: provider-reported token fields or directly observed character counts;
- `DERIVED_FROM_MEASURED`: arithmetic derived from measured fields;
- `NOT_MEASURED`: unavailable evidence.

The ledger may record:

- input/output tokens when reported;
- cache-read/cache-write tokens when reported;
- uncached input using Pi's normalized `input` bucket;
- tool calls;
- wall time;
- tool queue time;
- raw/visible character counts for reversible compaction;
- content/reducer/cache-mode labels.

Parent and child writers serialize the efficiency ledger through a bounded cross-process lock before append/compaction. Efficiency data never establishes correctness. Quality stays verifier-owned.

## 6. Runtime Waste Learner

`lib/runtime-waste-learner.mjs` summarizes recent durable evidence instead of guessing where UES is slow.

```cmd
ues optimize-report
```

can surface measured findings such as:

- repeated tool signatures;
- tool queue pressure;
- interrupted/dangling tool calls;
- high compaction recall demand;
- provider recovery cost.

Metrics UES cannot currently measure exactly, such as exact provider-billed tool-schema tax, are reported under `unavailable` rather than estimated silently.

### Trajectory Intelligence V2

The run inspector now distinguishes repeated work instead of treating every duplicate signature as the same problem:

- repeated reads/evidence recovery;
- repeated searches;
- repeated mutations/process work;
- blocked, interrupted and failed tool calls;
- queue delay and hidden-output verification pipelines.

`ues run-inspect last` remains observational: it does not suppress a repeated call merely because the signature matches. Repeated mutations in particular are evidence to investigate, not permission to deduplicate side effects.

Task telemetry summaries also expose nullable measured stage averages for provider wait, model generation, tool execution/result processing, verification and LSP primary/fallback time. Missing stage timing stays unavailable rather than being reconstructed from wall time.


## 7. Solution Economy Gate

`lib/solution-economy.mjs` adds a bounded writer-role contract inspired by minimal-solution engineering patterns:

1. understand the actual repository flow first;
2. reuse an existing repository helper/pattern when correct;
3. prefer standard-library support;
4. prefer native framework/platform primitives;
5. prefer an already-installed dependency before introducing another;
6. only then add the smallest complete implementation.

The gate explicitly forbids removing explicit requirements, validation, data-loss/error handling, security, accessibility, compatibility, required observability or verification just to reduce line count.

For high-risk work, independent correctness verification dominates solution economy.

## 8. One-command paired real-model trial

```cmd
ues trial --model <provider/model> --thinking <level>
```

wraps the existing Pi-native evaluator and defaults to:

- `--suite live`;
- `--mode both`;
- `--trials 3`;
- `--keep`.

This is a convenience surface, not a new benchmark methodology. Baseline and UES still run through the existing isolated evaluator/grader path.

A deterministic `npm run eval:v15.7` PASS does not prove a real model is faster, cheaper or more accurate. Those claims require the paired provider run.

## 9. Durable execution ownership fencing

`lib/execution-ownership.mjs` adds a bounded lease around child runtime execution.

- parent CLI/RPC launch claims and heartbeats the effective Runtime Epoch lease;
- the child receives the owner token and checks the lease before every tool call;
- a replacement parent process may take over an expired/abandoned lease;
- a child carrying a stale owner token is blocked before the next tool side effect;
- lease files are atomic and protected by a bounded cross-process lock.

For explicit same-session provider recovery, UES preserves the prior Runtime Epoch identity when selecting the RPC pool worker. The continuation prompt is a new user turn, not a privileged context/policy change, so this avoids accidentally turning "same-session recovery" into a fresh worker.

This fencing complements the process-tree supervisor and durable journal. It is not claimed as a distributed lock across machines and does not replace normal child termination.

## 10. Safety and quality invariants

V15.7 does not weaken:

- selected model thinking level;
- independent verifier / integration / visual gates;
- Evidence Store and exact raw-output recovery;
- dirty-work and local `.env` guards;
- workspace containment and destructive-command protection;
- hash-guarded write checkpoints;
- fail-closed incomplete diagnostics;
- Repo Map V3 / Semantic Index V3;
- Holdout D evidence history;
- V15.6 durable run journal and no-blind-replay recovery.
- V15.7 durable execution ownership fencing; a stale child cannot continue tool side effects after its parent lease is replaced or expires.

## 11. Release gate

```cmd
npm run eval:v15.7
npm run release:verify
```

`prepublishOnly` continues to execute the complete release gate.

Real-model performance remains a separately reported measured result.
