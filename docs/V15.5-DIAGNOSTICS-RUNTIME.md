# V15.5 Diagnostics & Runtime Intelligence

V15.5 merges the diagnostics/runtime-performance roadmap with the most useful
runtime contracts inspired by OpenCode, Claude Code and Codex without rewriting
UES or weakening its verification model.

## Runtime changes

1. **Telemetry V2 compatibility** — Pi compact token aliases plus nullable,
   non-overlapping provider/model/tool/LSP/verification stage fields.
2. **LSP Diagnostics V2** — server capability capture, dynamic registration,
   push diagnostics cache, lost-first-push recovery, and LSP 3.17 pull
   diagnostics only when advertised.
3. **LSP lifecycle** — the existing managed shutdown → exit → bounded
   process-tree cleanup remains authoritative; a diagnostics timeout stays a
   request-level event and does not kill a healthy session.
4. **Large-file diagnostics** — deterministic TypeScript fallback starts sooner
   for M/L/XL files while primary LSP remains enabled.
5. **Tool Concurrency Contract V1** — bounded reads/searches are explicitly
   parallel-safe; writes/process/unknown tools fail serial.
6. **Policy Snapshot V2** — child tool exposure and safety restrictions produce
   a deterministic snapshot ID; RPC warm reuse is keyed by that ID.

## Existing mechanisms intentionally retained

Post-write generation/stale rejection/coalescing, Evidence Store, independent
verifier, integration verifier, visual verifier when required, completion
auditor, dirty-work guard, local .env guard, destructive-command protection,
workspace containment, Repo Map V3, Semantic Index V3, Holdout D and thinking
policy are not relaxed.

## Diagnostics truth contract

- `complete: false` is never clean.
- A pull result is usable only when the server advertised pull support and
  returned a full `items` array.
- A missing/evicted push can cause a versioned full-content re-sync; the
  re-sync requests new evidence and never synthesizes a result.
- Large-file routing never skips the primary LSP lane in V15.5.

## Verification

`npm run release:verify` includes `eval:v15.5`, covering token aliases,
large-file fallback timing policy, first-push recovery, pull diagnostics,
concurrency classification and policy inheritance.

Deterministic tests are not evidence of real-model quality. Release reports must
state **REAL-MODEL A/B = MEASURED** or **REAL-MODEL A/B = NOT MEASURED**. The
repository does not invent a speedup/pass-rate claim when live model evaluation
was not run.
