# V16.5 External Research Notes

Architecture-only study. No source copied. All implementations in this repository are native
to the existing UES modules listed in the mapping column.

## 1. `steipete/oracle`

| Direction | Pattern | UES mapping |
| --- | --- | --- |
| Adopted | Bounded context bundle built *before* any provider call; `--render`/`--dry-run` prints exactly what would be sent, with no credentials and no network | `lib/skill-capsule.mjs` compiles a bounded capsule and records `skillCapsuleChars` / `rawSkillCharsAvoided` before the child prompt is built |
| Adopted | Readiness/doctor that reports provider readiness without exposing credentials | `lib/reasoning-doctor.mjs` (read-only, surfaced through `ues doctor`) |
| Adopted | Sessions stored under a durable directory so long answers can finish in background and be replayed | Already present: `lib/subagent-artifacts.mjs` + Evidence Store; V16.5 adds `rawEvidenceAvailable` on the handoff capsule instead of a second session store |
| Adopted | Follow-up limited to *supported* providers/conversations | Already present: V16.4 bounded follow-up budget in `lib/followup-budget.mjs` |
| Adopted | Usage/cost recorded per model in one session | Reused: `lib/run-telemetry.mjs` provider-token rows; V16.5 never invents token values |
| Rejected | Selecting files with user globs (`--file 'src/**/*.ts'`) as the primary context API | UES context is evidence-driven from the repo map; user-supplied globs would bypass ranking and provenance |
| Rejected | Multi-provider panel in a single run | UES DeepSeek Web is a single consultant lane; a panel would multiply untrusted external surface for no measured benefit |

## 2. `mjakl/pi-subagent` (high priority)

| Direction | Pattern | UES mapping |
| --- | --- | --- |
| Adopted | Fresh child context is the default; parent-snapshot cloning is an *exception*, flagged as expensive and authority-carrying | `lib/subagent-fabric.mjs` `buildChildContext()` defaults to `fresh`; parent cloning is refused unless explicitly requested and depth/cycle guards pass |
| Adopted | One isolated `pi` process per child, no shared memory, no sibling visibility | Reused: existing Pi child spawn in `pi/extensions/ues.ts`; V16.5 adds identity/ownership records, does not add a second process framework |
| Adopted | Inactivity watchdog measured on *child RPC stdout only*, independent of absolute wall-clock timeout | `lib/subagent-fabric.mjs` `createChildWatchdog()` — two independent timers with distinct receipts |
| Adopted | Depth guard + cycle guard over the ancestor stack, propagated by environment variables | `delegationDepth` / `delegationStack` on the child record; hard max depth 2 |
| Adopted | Partial output preserved on timeout with a distinct status | `finalizeSubagentArtifact` already persists `aborted`/`failed`; V16.5 handoff capsule keeps the raw ref on failure |
| Adopted | Model-facing result wrapper reports N/M succeeded, statuses stay visible | `lib/verified-handoff.mjs` capsule has a stable envelope plus per-field budget |
| Rejected | Named persistent child sessions (`session: "api-review"`) as the default multi-turn path | UES already has Evidence Store + durable run journal; a second durable conversation store duplicates state and weakens run-journal authority |
| Rejected | Concurrency default 10 | V16.5 hard-bounds active children to 2 (configurable max 3) |
| Rejected | TUI-expanded raw transcript viewer | V16.5 is observer-only; raw transcripts are Evidence-Store refs, not UI content |

## 3. `tintinweb/pi-subagents`

| Direction | Pattern | UES mapping |
| --- | --- | --- |
| Adopted | Fleet/status view showing one line per agent with state and elapsed time | `lib/agent-progress-observer.mjs` renders the same tree from bounded state, no GUI |
| Adopted | `get_subagent_result` / steer separation: observe and steer are distinct operations | Observer emits state only; steering stays with the existing parent Pi RPC control |
| Adopted | Child transcripts and token spend roll up to the immediate delegator | `childQueueMs`/`childExecutionMs`/`handoffMs` roll up to the parent delegation record |
| Rejected | Scripted `node:vm` workflow DSL (`agent()`, `parallel()`, `pipeline()`) | Adds a second orchestration language on top of the UES controller and task graph — explicitly out of scope |
| Rejected | Allowlist-driven *nested* subagents with per-child tool grants | Nested privilege boundary would multiply tool surfaces; UES caps depth at 2 and keeps role tools fixed by the agent catalog |
| Rejected | Cron-scheduled subagents | UES already has bounded, evidence-gated `ues-trial` promotion instead of an open scheduler |

## 4. `headroomlabs-ai/headroom`

| Direction | Pattern | UES mapping |
| --- | --- | --- |
| Adopted | Live-zone-only compression: frozen prefix stays byte-identical so provider cache survives | Already present: V15.7 provider cache stability + content router; V16.5 capsules are appended live-zone only and never rewrite the stable prefix |
| Adopted | Reversible compression with on-demand retrieval of the original | Already present: `lib/reversible-context.mjs` + Evidence Store; reused for raw child output |
| Adopted | Shared compressed handoff between agents | `lib/verified-handoff.mjs` — compact capsule in parent context, raw in Evidence Store |
| Rejected | Adding a `headroom-ai` dependency | UES already implements reversible context natively; a dependency would add supply-chain surface without new capability |

## 5. `DietrichGebert/ponytail`

| Direction | Pattern | UES mapping |
| --- | --- | --- |
| Adopted | Host-agnostic skill core with a thin per-host adapter | `global-config/skills/*/SKILL.md` stays the portable core; `lib/skill-registry.mjs` is the host-neutral contract; the Pi adapter is the only host-specific part |
| Adopted | Small skills that compose instead of one giant skill | Skill Capsule composes several skills into one bounded block instead of concatenating whole files |
| Adopted | Stale generated artifacts fail the test suite | V16.5 registry contracts are generated from one table and asserted in tests; the README section gate fails closed on the rewrite contract |
| Rejected | Always-on ruleset injected every turn | Contradicts the V16.5 goal of reducing repeated context |
| Rejected | Dropping safety guards for token savings | Explicitly forbidden; safety invariants are unchanged and enforced regardless of surface |

## 6. `JuliusBrussee/caveman`

| Direction | Pattern | UES mapping |
| --- | --- | --- |
| Adopted | Narrow output contract per skill | `outputContract` field on every skill contract plus the bounded handoff envelope |
| Adopted | Explicit side-effect boundary in the skill text | `forbiddenActions` + `sideEffectClass` on every contract |
| Adopted | Small model-facing instruction blocks; full text only on demand | `compileSkillCapsule()` (bounded) with `expandSkillCapsule()` (explicit) |
| Adopted | Payload verbatim: code, paths, numbers, error text never compressed | Capsule selection only removes prose; `constraints` sections are never truncated |
| Rejected | Aggressive output-style rewriting of model prose | Out of scope for a runtime package and would break evidence legibility |

## 7. `bestagentkits/cloud-harness-mcp`

| Direction | Pattern | UES mapping |
| --- | --- | --- |
| Adopted | Workspace lifecycle with explicit open/close and guaranteed teardown of owned child processes | `finalizeChild()` always emits a completion receipt, including on timeout and cancellation |
| Adopted | Lease/TTL bound on any owned resource | Delegation depth/cycle guards + bounded child timeout + bounded parallel writer count |
| Adopted | Structured tool result with a stable envelope, not free text | `Verified Handoff Capsule` schema |
| Adopted | Idempotency key on lifecycle open | Run-scoped child IDs derived from `(parentId, taskHash, role)` |
| Rejected | Docker workspace control plane, opaque workspace IDs, cloud transport | Would turn UES into a cloud service; explicitly out of scope |

## Rejected themes (cross-repo)

- Second process/orchestration framework (all repos that offer one).
- Concurrency defaults above 3 children.
- Nested subagent privilege boundaries.
- Persisting a second child-conversation store.
- Any claim of model-quality improvement without live measurement.
