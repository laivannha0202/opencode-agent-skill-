# V14.1 Quality-Preserving Performance Fabric

Status: incremental V14.1 work on top of `14.0.0-beta.1`.

## Goal

Increase throughput for weak models without lowering reasoning effort or weakening UES completion gates. V14.1 removes model-visible noise before it removes reasoning, verification, or evidence.

## Non-regression invariants

The default path keeps these properties unchanged:

- inherited Pi thinking level is preserved;
- executor work still requires independent verification;
- high-risk and long-horizon work keeps plan, scope, sandbox, retry, fresh-evidence and integration-verification gates;
- raw evidence remains recoverable;
- no external optimizer is installed, enabled, or wrapped around Pi automatically;
- optimization failure is fail-open: UES returns raw output rather than hiding evidence.

## Reversible model-visible output

`lib/performance-fabric.mjs` bounds oversized UES deterministic CLI output using a head / high-signal lines / tail preview. Before any reduction, the exact original is written to the content-addressed Evidence Store.

The compact result includes an `evidence:sha256:...` handle. The original can be recovered with:

```text
ues store get evidence:sha256:<hash>
```

Small outputs are returned unchanged. `UES_MODEL_VISIBLE_OUTPUT_LIMIT` controls the Pi adapter threshold and defaults to 64 KiB.

This layer does not rewrite model prompts, source files, verifier reports, or the model's thinking configuration.

## Compact hierarchy

`ues hierarchy` now returns bounded routing data by default: L0/L1 summaries, scores, reasons, counts, top files and top symbols. Complete file arrays remain available explicitly:

```text
ues hierarchy "<query>" . --full
```

The adaptive child context was already bounded separately; this change protects direct `ues_cli` use from accidentally injecting very large scope payloads.

## Deterministic read-only fast path

Structured tasks classified by Dynamic Workflow as `deterministic` skip the executor only when `taskWriteFiles()` is empty. The read-only `ues-verifier` still runs with the inherited thinking level and must return PASS. Any task with create/modify/test/delete scope keeps the existing executor → verifier path.

This makes verification-only plan steps such as test, typecheck, lint, compile or explicit verify-command tasks consume one specialist model call instead of two without removing the independent evidence gate.

## Minimal-solution executor policy

The executor now prefers the first maintainable solution that fully satisfies the task:

1. reuse an existing codebase primitive;
2. use the standard library or native platform capability;
3. use an already-installed dependency;
4. write the smallest necessary new implementation.

This is inspired by Ponytail's minimal-solution approach, but UES explicitly forbids using brevity as a reason to weaken validation, error handling, security, data integrity, accessibility, compatibility, tests, observability, or explicit requirements. The rule is scoped to implementation; independent verifiers remain independent.

## External providers

Capability Fabric exposes an `output.compaction` capability with these providers:

- `ues-reversible-compactor`: built-in, default, reversible, non-lossy raw recovery;
- `rtk-cli`: optional detected command provider for shell-output compaction;
- `caveman-cli`: optional experimental provider;
- `headroom-cli`: optional experimental provider.

Detection is not activation. The built-in provider has the highest default score, so installing an external command does not silently alter UES behavior.

RTK is kept outside the Pi hook chain to avoid competing command-rewrite hooks. Caveman remains external because its engine-linked runtime directories are BSL-1.1; UES does not vendor those components into the MIT core. Headroom remains experimental and its output-effort shaping is not enabled by UES.

## Promotion gate

An external provider should become a default only after a paired baseline-vs-provider evaluation on the same model and task set shows all of the following:

```text
pass rate >= baseline
false PASS rate <= baseline
safety/required gates >= baseline
and latency or token usage materially improves
```

Until that evidence exists, external compressors remain optional capabilities rather than default execution policy.
